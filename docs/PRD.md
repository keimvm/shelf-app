# Shelf PRD

仮称 **Shelf**（Bundle ID 仮：`dev.keimvm.Shelf`）。ファイルやテキストを一時的に置いておける、フローティングシェルフの macOS ネイティブアプリ。
実装は公開 macOS API のみで独自に設計する。設計の前提になる OS の挙動の検証結果は [verification.md](verification.md) を参照。

本書は 0.2 の仕様。0.1 からの変更とその理由、0.2 の公開後の変更は §9 にまとめる。

## 1. 目的

ファイルを別の場所やアプリへ運ぶとき、ドラッグ元とドラッグ先を同時に画面に出すのは手間がかかる。
ドラッグ中にカーソルを振るだけで「一時置き場」を出し、ファイルをいったん置いて、後から好きなアプリへドラッグして渡せるようにする。

### 成功の条件

- ドラッグ中のシェイクから 1 操作でシェルフが出る。
- 置いたファイルをどのアプリへも普通のドラッグで渡せる。
- シェルフを使っても**元ファイルは移動・変更されない**。

## 2. 設計の原則

仕様の判断はすべて次の原則から導く。原則どうしがぶつかるときは、上にあるものを優先する。

| # | 原則 | 具体的には |
|---|---|---|
| P1 | **原本を守る** | 原本に一切書き込まない。取り出しは常にコピー。アプリが消してよいのは自分で書いた一時ファイルだけで、それ以外の場所は消せないようにする（N1） |
| P2 | **作業の流れを奪わない** | シェルフを出しても操作しても、使っているアプリからフォーカスを移さない。全 Space・フルスクリーンの上に出る |
| P3 | **権限は最小にする** | 必要のない権限・Entitlements を持たない。ユーザーが渡したもの以外は読まない。ドラッグの内容はドロップされるまで読まない。使っていない機能のためにマウスを監視しない |
| P4 | **何も残さない** | シェルフは一時置き場。書き出したファイルは項目がシェルフを離れたら消え、アプリの終了時にも消える |
| P5 | **シンプルにする** | 概念・設定・経路を増やさない。同じことをする方法は 1 つで足りるなら 1 つにする |
| P6 | **事実で決める** | OS の挙動はスパイクで確かめ、事実・推測・未確認を区別して記録する。確かめられないことは未確認と明記する |

## 3. 対象ユーザーと利用場面

- Finder とアプリ間でファイルを頻繁に運ぶ macOS ユーザー。
- 例：
  - 複数のフォルダから集めたファイルを、まとめてメールに添付する。
  - Safari の画像やテキストを一時的に置き、別のアプリへ渡す。
  - フルスクリーンのアプリへ、別の Space にあるファイルを持ち込む。

## 4. ユーザーストーリー

1. ファイルをドラッグしている最中にカーソルを振ると、カーソルのそばにシェルフが現れる。シェルフが別の場所に出ていれば、カーソルのところへ来る。
2. シェルフにファイルを落とすと、そのファイルがシェルフに並ぶ。複数のファイルをまとめて置ける。
3. シェルフの項目を 1 つ、または全部まとめて、別のアプリへドラッグして渡せる。
4. ブラウザのテキストや URL、ファイルを直接持たない画像（File Promise）もシェルフに置ける。
5. シェルフはクリックしてもドラッグ元のアプリからフォーカスを奪わず、移動できる。隠しても中身は残り、メニューバーのアイコンが件数を示す。
6. どのアプリを使っていても、ショートカットキーでシェルフを表示・非表示にできる。
7. 不要になった項目は、× または右クリックでシェルフから外せる。右クリックでシェルフを空にもできる。

## 5. 機能要件

| ID | 機能 | 要件 |
|---|---|---|
| F1 | メニューバー常駐 | Dock に出ない（`LSUIElement`）。アイコンは空なら `tray`、項目があれば `tray.full` と件数。メニュー：シェルフを表示／隠す（ショートカットを併記）/ シェルフを空にする / 表示のショートカット…/ シェイク起動の ON/OFF / 感度（標準・高・最高）/ ログイン時に開く / 終了 |
| F2 | ドラッグ検知 | 他アプリで始まったドラッグのうち、ドラッグ用ペーストボードが更新されたものを「外部ドラッグ中」とみなす。自アプリ発のドラッグは対象外。シェイク起動がオフの間はマウスを監視しない |
| F3 | シェイク検知 | 外部ドラッグ中のカーソル軌跡から、方向の反転が時間窓内に規定回数あればシェイクと判定する。1 回のドラッグで発火は 1 回まで。カーソルがシェルフ上にあるときは発火しない |
| F4 | シェルフ | シェルフは 1 つ。隠すボタン（−）がカーソルの下に来る位置に出す（本体はカーソルの右下になり、狙っていた項目を覆いにくい。画面からはみ出す分はずらす）。すでに出ていれば、カーソルの位置へ移す。アプリをアクティブにしない。他のウィンドウより手前、全 Space・フルスクリーン上にも表示する。上部のハンドルで移動、ボタン（−）で隠す。隠しても項目は残る |
| F5 | 受け入れ | ファイル URL（複数可）、File Promise、プレーンテキスト、Web URL |
| F6 | 取り出し | 項目を個別、または全項目まとめて他アプリへドラッグできる。送り出す操作は `.copy` のみ許可する。取り出した項目はシェルフから外れる |
| F7 | 空になったら隠す | 取り出しや F14 で項目がなくなったシェルフは自動で隠す。File Promise の受信待ちがあれば保留し、全件の受信が成功または失敗で完了した時点でも空なら隠す |
| F8 | 一時保持 | 通常のファイルは参照（URL + bookmark）だけを保持する。Promise / テキスト / URL はアプリの一時ディレクトリにファイルとして作る |
| F9 | 一時ファイルの掃除 | 書き出したファイルは、その項目がシェルフを離れたら削除する（取り出しの場合は、宛先のコピーが終わるのを待つため 30 秒後）。アプリの終了時と起動時に一時ディレクトリごと削除する |
| F10 | 原本の追従 | 原本が移動・リネームされたら bookmark で新しい場所を解決する。解決できない、またはゴミ箱にある場合は項目を「見つかりません」と表示し、取り出し不可にする。戻されたら再び取り出せる |
| F11 | サムネイル | ファイルアイコンとファイル名を表示する |
| F12 | 表示のショートカット | 全アプリで効くショートカットでシェルフを表示・非表示にする。既定は ⌃⌥⌘N。メニューから変更・解除でき、設定は保持する（0.1 で選んだショートカットを引き継ぐ）。⌃・⌥・⌘ のどれかを含む組み合わせ、または F1〜F20 に限る。ほかのアプリが使っていて登録できない組み合わせは保存しない |
| F13 | （欠番） | 0.2 のサービス「Shelf に置く」は削除した（§9.1）。ID は振り直さない |
| F14 | 外す・空にする | 項目にポインタを乗せると、アイコンの左上に × が出る。クリックでその項目をシェルフから外す。項目を右クリックすると「Finder に表示」「シェルフから外す」「シェルフを空にする」、項目のない所を右クリックすると「シェルフを空にする」。外した項目の書き出したファイルはすぐ削除する。「見つかりません」の項目は Finder に表示できない |

## 6. 非機能要件

| ID | 区分 | 要件 |
|---|---|---|
| N1 | 原本の保護 | アプリは原本ファイルに一切書き込まない。取り出しは `.copy` のみとし、ドロップ先による移動も起こさない。削除は一時ディレクトリの中に限り、外の URL を渡されても何もしない |
| N2 | Sandbox | App Sandbox を有効にする。Entitlements は `app-sandbox`、`files.user-selected.read-write`、`files.bookmarks.app-scope` の 3 つに限る。一時的な例外（temporary-exception）と Apple Events は使わない |
| N3 | 権限 | Accessibility・オートメーション・フルディスクアクセスなどの権限を要求しない。読めるのは、ユーザーがドロップで渡したものだけ |
| N4 | 性能 | ドラッグしていない間はイベント処理以外の処理をしない。シェイク起動がオフならマウスの監視自体を外す。ドラッグ中のシェイク判定は軽量（サンプル数を時間窓で制限）にする |
| N5 | 一時データ | 一時ファイルは Sandbox コンテナの一時ディレクトリ内に限る。項目が離れたら消し、終了時には残さない |
| N6 | 依存 | 外部ライブラリを使わない。Swift + AppKit、macOS 14 以降 |
| N7 | 独立性 | 既存アプリのコード・アセット・文言・名称を使わない |
| N8 | テストの隔離 | 単体テストはアプリの中で動くが、そのときアプリは組み立てない（ショートカットの登録・一時ファイルの掃除をしない）。同じコンテナを使う実行中の Shelf のファイルに触れないため |

## 7. アーキテクチャ

### 7.1 技術選定

- **Swift + AppKit**。ウィンドウレベル、非アクティブパネル、グローバルイベント監視、ドラッグ API を直接扱う必要があるため、SwiftUI ではなく AppKit を主体にする。
- **Xcode プロジェクト**（`Shelf.xcodeproj`）。Info.plist・Entitlements・署名・Sandbox を標準の手順で扱え、`xcodebuild` でビルドとテストができる。ファイル参照の管理を減らすため、フォルダ同期グループ（`PBXFileSystemSynchronizedRootGroup`）を使う。
- 最小 OS は macOS 14。

### 7.3 処理の流れ

```
leftMouseDown ──▶ GlobalDragMonitor: ドラッグ用ペーストボードの changeCount を記録
leftMouseDragged ─▶ changeCount が変化していれば「外部ドラッグ中」
                    └▶ ShakeDetector.add(point, time)
                         └▶ シェイク成立 ──▶ ShelfController.show(near: point)
leftMouseUp ────▶ 状態をリセット

ShelfDropView ──▶ InboundReader ──▶ Shelf.append(items)
                            ├ ファイル URL ……… FileReference（参照のみ）
                            └ Promise/テキスト/URL ─▶ TemporaryStorage に書き出し
ショートカット（F12）・メニュー ─▶ ShelfController.toggle
ShelfItemView / 「すべて」──▶ Shelf.refreshFiles（bookmark を解決）
                    └▶ ShelfDragSource（.copy）──▶ 他アプリ
                         └ 終了時 ─▶ ShelfController.remove（30 秒後に一時ファイルを削除、空なら隠す）
× ・項目のメニュー「外す」──▶ ShelfController.remove（すぐ削除、空なら隠す）
メニュー「空にする」────────▶ ShelfController.clear
Shelf の変化・表示状態 ──▶ StatusItemController.update（件数）
```

### 7.4 主要な設計

**ドラッグ検知（F2）**
- `NSEvent.addGlobalMonitorForEvents(matching: [.leftMouseDown, .leftMouseDragged, .leftMouseUp])` で他アプリのマウス操作を受ける。自アプリ上の操作はローカルモニタで受け、両方を 1 つの座標列にまとめる（外部ドラッグ中でも、自パネル上の座標はローカルモニタ側に届く。verification.md K6）。
- マウス押下時の `NSPasteboard(name: .drag).changeCount` を記録し、ドラッグ中に値が変わったら外部ドラッグとみなす。ペーストボードの内容はドロップされるまで読まない（P3）。
- モニタはシェイク起動がオンの間だけ置く。メニューでオフにすると外し、オンにすると置き直す（P3, N4）。
- Sandbox 下でもドラッグ中のイベントがグローバルモニタに届くことを確認済み（verification.md U1）。届かない環境に備え、マウス押下中だけ `NSEvent.mouseLocation` をタイマーで取得する方式を代替として残す。

**シェイク判定（F3）**
- 入力は時刻付きの座標。最小移動量未満の動きは無視し、移動方向のベクトルを区間ごとに求める。前の区間と同じ向きに進んでいる間は区間の終点をカーソルに合わせて進め、次の区間が折り返し点から始まるようにする（振り幅が区間長の 2 倍未満だと、始点が振れの中央に残って判定が止まるため。verification.md §3）。
- 前の区間との角度が大きく変わった（120° 超）ら「反転」と数える。方向は問わない。
- 直近の時間窓の反転が規定回数に達したらシェイク成立。
- 感度は「反転回数」「区間の最小長」「時間窓」の組で表す。値は Phase 5 で調整した：標準 4 回・24pt・0.9 秒、高 3 回・24pt・0.8 秒、最高 3 回・20pt・1.1 秒（反転角はいずれも 120°）。照準を合わせる動き（行き過ぎて戻し、少し進める）で反転が 2 回起きるため、どの段階も 3 回以上とする。
- 時刻を外から渡すことで、UI なしで単体テストできるようにする。

**シェルフ（F4, F7）**
- シェルフは 1 つ。`ShelfController` がパネルを最初に表示するときに 1 枚作り、以後は表示と非表示（`orderOut`）を繰り返す。隠しても `Shelf` の項目と一時ファイルはそのまま。
- 表示するとき、シェルフがすでに出ていてカーソルがその上になければ、隠すボタンがカーソルの下に来る位置へ移す（シェイクで「呼び寄せる」）。カーソルがシェルフ上にあれば動かさない。
- `NSPanel`、`styleMask` に `.nonactivatingPanel`。`level = .floating`、`collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary]`、`hidesOnDeactivate = false`。`isMovableByWindowBackground` は使わない（項目のドラッグでパネルごと動くため。verification.md K1）。`isMovable = false` にして透明タイトルバーによる移動も止める（タイトルバー内の「すべて」から取り出すとパネルも動くため。verification.md K7）。移動は上部のハンドルで `window.performDrag(with:)` を呼んで行う（`isMovable = false` でも動く）。
- 表示は `orderFrontRegardless`。アプリはアクティブにしない。
- この設定でフルスクリーン Space 上の表示と、非アクティブのままのドロップ受け付けを確認済み（verification.md U4）。
- 「フォーカスを奪わない」の確認には `NSApp.isActive` ではなく `frontmostApplication` を使う（パネルがキーになると `isActive` は `true` になるため。verification.md K5）。
- ハンドル左のボタンは「隠す」で、アイコンは × ではなく −（閉じると中身が消えると誤解させないため）。
- 項目がなくなったら隠す。File Promise の受信待ちがあれば、全件の成功・失敗が確定するまで隠さず、届いたファイルを残す。全件失敗して空のままなら、その時点で隠す。

**メニューバー（F1）**
- アイコンは項目の有無で `tray` / `tray.full` を切り替え、項目があれば件数をタイトルに出す。隠したシェルフに何かが残っていることを忘れないため（P4）。
- `ShelfController.onChange`（項目の変化と表示状態の変化）で更新する。

**受け入れ（F5）**
- `registerForDraggedTypes` に、ファイル URL、`NSFilePromiseReceiver.readableDraggedTypes`、文字列、URL を登録する。
- 優先順：ファイル URL → File Promise → URL → テキスト。
- `draggingEntered` は、ソース mask に `.copy` があれば `.copy`、なければ `.generic` を返す（Finder は `.generic` のみを渡すことがある。verification.md K4）。
- 自アプリ発のドラッグ（`draggingSource` が自分）のドロップは受け付けない（verification.md K3）。
- File Promise は `receivePromisedFiles(atDestination:)` で一時ディレクトリ内のドロップごとのフォルダへ受け取る（同名ファイルの衝突を避けるため）。受け取りのコールバックはバックグラウンドのキューで呼ばれるので、メインアクターに戻してから項目を追加する。届いたファイルから順にシェルフへ並べる。
- テキストは `.txt`（1 行目をファイル名にする）、Web URL は `.webloc`（ページ名、なければホスト名をファイル名にする）として一時ディレクトリに作る。名前が重複したら「名前 2」のように番号を付ける。長い名前は拡張子と連番を含めて UTF-8 で 255 バイト以内に収め、文字の途中で切らない。
- 既にシェルフにあるファイルを再度置いても、項目は増やさない。

**取り出し（F6）**
- 取り出しを始めるのは各項目のビューと、ハンドルバー右端の「すべて」（取り出せる項目数を表示）。どちらも `acceptsFirstMouse(for:)` で `true` を返す（他アプリが前面のときも 1 回目のクリックでドラッグできるように。verification.md K2）。アイコンや名前のクリックもこのビューで受ける。
- 取り出しは、そのビューで `mouseDown` を受けた後、3pt 以上動いた `mouseDragged` に限って開始する（外部ドラッグ中に迷い込む `mouseDragged` で誤って始まるため。verification.md K3）。
- 開始の直前に原本の場所を解決し直し（F10）、取り出せる項目のファイル URL を pasteboard writer にして `beginDraggingSession` を始める。「すべて」は全項目をまとめて送る。「見つかりません」の項目は送らず、それしかなければドラッグを始めない。
- `sourceOperationMaskFor` は、アプリの外へは `.copy`、アプリ内へは空を返す。Finder への同一ボリュームのドロップでも移動にならないことを確認済み（verification.md U3）。
- `draggingSession(_:endedAt:operation:)` で操作がなし以外なら、取り出した項目を `ShelfController.remove` で外す。書き出したファイルは 30 秒後に消す（宛先はドロップの後で非同期にコピーすることがあるため。推測）。

**一時保持（F8〜F10）**
- ファイルは受け取った時点で URL と bookmark を作って保持する。原本の中身もメタデータも変更しない。
- bookmark は app-scope の security-scoped bookmark とし、利用時に `startAccessingSecurityScopedResource` を呼ぶ。プロセス存続中はドロップで得たアクセス権が続くことを確認済みだが、原本の追従（F10）のため bookmark は作る（verification.md U3）。
- 原本の追従（F10）：カーソルがシェルフに入ったとき（`NSTrackingArea`、`.activeAlways`）と取り出しの直前に、bookmark を `.withSecurityScope` で解決する。解決した URL には `startAccessingSecurityScopedResource` を呼び、その項目がシェルフにある間アクセスを保つ（項目が外れたら止め、空になったらすべて止める）。stale なら新しい場所で bookmark を作り直す。解決できない、またはパスに `.Trash` / `.Trashes` を含む場合は「見つかりません」とする（bookmark はゴミ箱の中まで追うため）。bookmark は残すので、戻されれば再び見つかる。常時の監視はしない（N4）。
- 書き出したファイルの置き場は `FileManager.default.temporaryDirectory/Shelves/`（Promise はその下のドロップごとのフォルダ）。`TemporaryStorage.discard` は、渡された URL がこのディレクトリの中にあるときだけ削除し、Promise のフォルダは最後のファイルと一緒に消す。ディレクトリの外や、ディレクトリそのものは消さない（N1）。

**表示のショートカット（F12）**
- 登録は Carbon の `RegisterEventHotKey`。公開 API で、Sandbox 下でも Accessibility の権限なしで使える（N3）。`NSEvent.addGlobalMonitorForEvents` でのキー監視は権限が要るので使わない。
- 設定は `UserDefaults` にキーコードと修飾キーで保存する。「なし」は空の辞書で表し、既定値（⌃⌥⌘N）と区別する。キーは 0.1 と同じ `newShelfHotKey` のままにして、選んだショートカットを引き継ぐ。0.1 の設定 `placesFinderSelection` は起動時に削除する（P4）。
- メニューの「シェルフを表示／隠す」には、実際に登録できているショートカットだけを `keyEquivalent` で表示する。キーの文字は現在の ASCII 入力用レイアウトから求める（日本語入力中でも「N」と出すため）。
- 記録は、`.nonactivatingPanel` のパネルをキーにして受ける。メニューバーの項目から `NSApp.activate()` してもアプリはアクティブにならず、`NSAlert` ではキー入力を受けられなかった。パネルはアクティブにしなくてもキー入力を受けた（いずれも合成したクリック・キー入力で確認）。記録中は現在のショートカットの登録を外し、押した組み合わせがパネルに届くようにする。
- ほかのアプリがすでに登録している組み合わせは、押してもパネルに届かない（確認済み。推測：先に登録した側が受け取るため）。

**外す・空にする（F14）**
- × は項目のアイコンの左上に置き、ポインタがその項目の上にあるときだけ出す（項目が多いときに一覧を散らかさないため）。シェルフ全体の `NSTrackingArea`（`.mouseMoved`、`.activeAlways`）で、ポインタの下の項目を求めて切り替える。項目が外れると次の項目が同じ場所に来るので、一覧を作り直した直後にも求め直す（ポインタを動かさずに続けて外せるように）。
- 項目のビュー（`ShelfDragOriginView`）はクリックをすべて自分で受けて取り出しに使うが、× が出ている間は × のクリックだけ × に通す。× も `acceptsFirstMouse(for:)` で `true` を返す（verification.md K2）。
- 項目のビューの `menu(for:)` で、その項目のメニューを作る。「Finder に表示」は `NSWorkspace.activateFileViewerSelecting`（Finder がアクティブになるのは、ユーザーが Finder を開くよう選んだときだけ）。「シェルフから外す」と × は `ShelfController.remove` で、書き出したファイルはすぐ消す。
- 「シェルフを空にする」は、項目のメニューと、シェルフの背景のメニュー（項目のない所・ハンドルの右クリックがここまで上がってくる）に出し、メニューバーの同名の項目と同じ `ShelfController.clear` を呼ぶ。確認は出さない（メニューバーの「空にする」と揃える。原本は変わらない）。

**テストの隔離（N8）**
- 単体テストはアプリをホストにして動く。環境変数 `XCTestConfigurationFilePath` があるとき、`AppDelegate` は何も組み立てず、終了時の掃除もしない。

### 7.5 ビルドと配布

手順は [README](../README.md) に書く。

- ビルドは Release 構成で `build/DerivedData.noindex` に出す（`scripts/build.sh`）。成果物は `build/DerivedData.noindex/Build/Products/Release/Shelf.app`。
- 自分の Mac では `/Applications/Shelf.app` に置いて使う（`scripts/install.sh`）。
- 他の Mac には GitHub Releases で配る。`scripts/release.sh` が `ditto` で zip にして `v<MARKETING_VERSION>` として公開する。
- 署名は ad-hoc のまま。Developer ID の署名と公証は、自分以外に配るときに検討する。

## 9. 0.1 からの変更と理由

| 0.1 | 0.2 | 理由 |
|---|---|---|
| シェルフを最大 10 個まで開ける。11 個目は警告音 | シェルフは 1 つ。シェイクやショートカットで呼ぶと、今いる場所へ来る | P5。複数のシェルフは配置・上限・どのシェルフかという判断を生む。運ぶものを分けたい場面は少なく、1 つのシェルフから個別に取り出せば足りる |
| × で閉じると中身ごと消える | − で隠す。中身は残り、メニューバーに件数が出る。消すのは取り出し・「外す」・「空にする」だけ | P1・P4。閉じた拍子にブラウザから置いたテキストなどを失わないため。残っていることはアイコンで分かる |
| Finder の選択項目をショートカットで置く（Apple Events + 読み取り専用の例外 `/`、オートメーションの許可） | サービス「Shelf に置く」。どのアプリのファイル・テキスト・URL にも使える | P3。0.1 は便利さのためにディスク全体の読み取りと Finder の操作の権限を持っていた。サービスならシステムが選択とそのアクセス権だけを渡すので、Entitlements は 3 つに戻り、許可のダイアログもなくなる。Finder 以外のアプリでも使えるようになった。代わりに「表示」と「置く」のショートカットは別になる |
| 書き出したファイルはシェルフを閉じるまで残る | 項目がシェルフを離れたら消す。終了時にも消す | P4。シェルフが 1 つで長く開いているため、離れた項目のファイルを持ち続けない |
| シェイクがオフでもマウスを監視していた | オフならモニタを外す | P3・N4 |
| 項目を外す方法は取り出しだけ | 右クリックで「シェルフから外す」「Finder に表示」 | シェルフが長く残るため、要らない項目を外す手段が要る |
| 単体テストのホストでもアプリが組み立てられ、起動時の掃除が同じコンテナの一時ファイルを消しえた | テストのホストでは組み立てない | P1 の延長（ユーザーのデータを守る）。N8 |

### 9.1 0.2 の公開後の変更

| 0.2 | 現在 | 理由 |
|---|---|---|
| サービス「Shelf に置く」（⌃⌥⌘P）で、どのアプリの選択項目も置ける | 削除。置くのはドロップだけ | サービスのショートカットはシステムが持つ設定で、Sandbox のアプリからは変えられず、表示のショートカット（F12）のようにアプリで設定できない（verification.md §7）。アプリで設定できない経路は残さず、機能ごと外した。権限を増やして実現することはしない（P3） |
| 項目を外す方法は取り出しと右クリックの「シェルフから外す」 | 項目の × でも外せる。右クリックで「シェルフを空にする」 | 複数の項目を置いたとき、シェルフの上で個別に外す・まとめて消すため |

## 10. 受け入れ基準

0.1 の受け入れ基準（ドラッグ・シェイク・取り出し・追従・フォーカス）は 2026-10-22 にドライバによる実ドラッグで確認した（verification.md §3.4）。0.2 ではシェルフまわりのコードを組み替えたため、ドラッグを伴う項目は再確認が要る。

確認済み（2026-10-24、verification.md §6）：

- [x] `xcodebuild test -scheme Shelf` で全テスト（§9.1 の変更後は 74 件）が通る。テストの実行中にアプリが組み立てられない。
- [x] 終了すると一時ディレクトリが消える。
- [x] Entitlements が N2 の 3 つだけ。

画面で確認済み（2026-10-24、ユーザーの手で操作）：

- [x] 項目にポインタを乗せると左上に × が出て、外れると消える。× をクリックするとその項目だけが消え、ポインタを動かさなくても次の項目の × が出る。他のアプリが前面のときも 1 回目のクリックで外せる。× 以外の場所からは今までどおりドラッグで取り出せる。
- [x] 項目を右クリック、または項目のない所・ハンドルを右クリックして「シェルフを空にする」と、全項目が消えてシェルフが隠れる。
- [x] ⌃⌥⌘N・メニュー・シェイクでシェルフを出すと、隠すボタン（−）がカーソルの下に来て、本体はカーソルの右下に出る。シェイクで出た直後にそのまま離しても、シェルフに置ける。

手動確認の手順（未確認）：

- Finder からファイルをドラッグしてカーソルを振るとシェルフが出る。シェルフを画面の別の場所に出したまま、もう一度ドラッグして振ると、シェルフがカーソルのところへ来る。シェルフの上で振っても動かない。
- シェルフに置いたファイルを Finder・メール・Safari へドラッグするとコピーされ、原本が変わらない。全項目を取り出すとシェルフが隠れ、メニューバーのアイコンが `tray` に戻る。
- 項目を残したまま − で隠すと、メニューバーに件数が出る。⌃⌥⌘N で同じ項目のシェルフが出る。
- サービスメニュー（右クリック → サービス）に「Shelf に置く」が出ない。⌃⌥⌘P を押しても何も置かれない。
- 項目を右クリックして「シェルフから外す」と、その項目だけが消える。「Finder に表示」で原本が選択された Finder のウィンドウが開く。他のアプリが前面のときも右クリックでメニューが出る。
- メニューで「シェイクで開く」をオフにすると、振ってもシェルフが出ない。オンに戻すと出る。
- 0.1 でショートカットを変えていた場合、0.2 でも同じショートカットでシェルフが出る。

## 11. リスク

| リスク | 影響 | 対策 |
|---|---|---|
| Sandbox 下でドラッグ中のマウスイベントがグローバルモニタに届かない（U1） | シェイク検知ができない | 解消（届くことを確認）。ポーリングは代替として残す |
| ドラッグ用ペーストボードの読み取りでプライバシー確認が出る（U2） | 操作のたびにダイアログ | 解消（ドラッグ用は常に許可）。内容はドロップ時だけ読む方針は維持 |
| ドロップしたファイルへのアクセス権が切れる（U3） | 取り出し・サムネイルが失敗 | 解消（プロセス存続中は維持）。bookmark は受け取った直後に作成 |
| フルスクリーン上で表示されない・ドロップを受けない（U4） | 主要な利用場面で使えない | 解消（`.floating` で表示・受け付けを確認） |
| シェイクの誤検知・未検知 | 操作感の低下 | 感度 3 段階、1 ドラッグ 1 回の制限。照準の修正（反転 2 回）では発火しないよう全段階で反転 3 回以上。合成軌跡で調整済み（verification.md §3）で、実際の手での調整は残る |
| 隠したシェルフの項目を忘れる | 一時ファイルが残り続ける | メニューバーに件数を出す。終了時に消える |
| 一時ファイルの残留 | ディスクの浪費 | 項目が離れたとき・終了時・起動時に削除 |
